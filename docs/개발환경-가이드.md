# kdt 앱 개발환경 가이드

> 처음 이 프로젝트를 받는 사람을 위한 문서입니다.
> **위에서부터 순서대로** 따라 하세요. 중간을 건너뛰면 원인을 알 수 없는 에러가 납니다.

---

## 0. 시작하기 전에 — 이것만은 먼저 이해하고 가세요

여기서 헤매는 사람의 90%는 아래 3가지를 몰라서 헤맵니다.

### ① "앱이 안 돼요"는 두 가지 완전히 다른 상황입니다

```
   [ A. 빌드 실패 ]                    [ B. 앱은 뜨는데 로그인 실패 ]
   앱 화면이 아예 안 뜬다               앱 화면은 잘 뜬다
   터미널에 빨간 에러가 쏟아진다         로그인 누르면 빨간 메시지가 뜬다
        ↓                                    ↓
   내 PC 환경 문제                       서버가 꺼져 있는 것
   (JDK / SDK 설정)                     (내 잘못이 아님, 고칠 수도 없음)
```

**둘을 구분하지 못하면 며칠을 태웁니다.** 문제가 생기면 가장 먼저 물어보세요:
**"앱 화면이 뜨나요, 아니면 뜨기 전에 멈추나요?"**

### ② 버전은 대부분 프로젝트가 정해줍니다. 내가 맞출 건 딱 하나입니다

| 항목 | 누가 정하나 | 내가 할 일 |
|---|---|---|
| Gradle 9.1.0 | 프로젝트 파일에 박혀 있음. 없으면 자동 다운로드 | **없음** |
| AGP 9.0.1 / Kotlin 2.3.20 | 프로젝트 파일에 박혀 있음 | **없음** |
| Flutter 3.44.x | 프로젝트가 요구 | 설치만. **업그레이드/다운그레이드 금지** |
| **JDK (자바)** | **프로젝트에 없음 — 내 PC 설정** | **이것만 확인하면 됨** |

버전 에러가 났다고 프로젝트 파일의 숫자를 고치지 마세요. 그게 문제를 3배로 키웁니다.

### ③ 서버는 이 프로젝트 안에 없습니다

이 저장소는 **앱(화면)만** 들어 있습니다. 로그인·회원가입·로봇제어·센서데이터를 처리하는 서버는
**팀의 서버 담당자 PC에서 따로 돌아갑니다.**

```
  [ 내 폰/에뮬레이터 ]  ──HTTP──▶  [ 서버 담당자 PC ]  ──▶  [ DB ]
       kdt 앱                       REST API (12345)
                       ──MQTT─▶     MQTT 브로커 (1883)
```

**그 사람이 서버를 안 켜면, 앱을 아무리 고쳐도 로그인은 100% 실패합니다.**

## 1. 설치 — 처음 한 번만

### 필요한 것

| 프로그램 | 버전 | 비고 |
|---|---|---|
| Flutter | **3.44.x** | Dart 3.12.2 포함 |
| Android Studio | 최신 | JDK와 에뮬레이터가 같이 딸려옴 |
| **JDK** | **17 ~ 25** | Android Studio에 21이 들어있어서 보통 그냥 해결됨 |
| Android SDK | **API 36** | Android Studio에서 설치 |

> **JDK 범위 17~25는 추측이 아닙니다.** Gradle 9.1.0 공식 문서에 이렇게 적혀 있고,
> 실제로 JDK 11 / 17 / 21 / 25 / 26으로 빌드를 다 돌려서 확인했습니다.
> `A JVM version between 17 and 25 is required to execute Gradle.`
> `JVM 26 and later versions are not yet supported.`
>
> - JDK 11 → 실패 (`Gradle requires JVM 17 or later to run`)
> - JDK 17 / 21 / 25 → **성공**
> - JDK 26 → 실패 (`JdkImageTransform` / `jlink` 에러)
>
> `brew install openjdk` 로 자바를 깔면 지금 **26**이 설치됩니다. 주의하세요.

### 설치 확인


`[✓]` 가 아닌 항목이 있으면 그 줄에 적힌 안내대로 처리합니다. 자주 나오는 것:


## 2. 자바(JDK) 확인 — 가장 중요한 단계

```bash
flutter doctor -v | grep -A3 "Java binary"
```

이런 식으로 나옵니다:

```
• Java binary at: /Applications/Android Studio.app/Contents/jbr/Contents/Home/bin/java
  This is the JDK bundled with the latest Android Studio installation on this machine.
• Java version OpenJDK Runtime Environment (build 21.0.9+-...)
                                                    ↑ 이 숫자가 17~25 사이면 OK
```

### ⚠️ 헷갈리기 쉬운 점 두 가지

**첫째, 터미널의 자바와 Flutter의 자바는 다를 수 있습니다.**

```bash
java -version          # ← 내가 터미널에서 쓰는 자바
flutter doctor -v      # ← Flutter가 빌드에 실제로 쓰는 자바  ★ 이게 중요
```

Flutter는 이 순서로 자바를 고릅니다. 위에서 찾으면 아래는 무시합니다.

```
1. flutter config --jdk-dir 로 지정한 경로
2. Android Studio 번들 JDK          ← 보통 여기서 결정됨
3. 환경변수 JAVA_HOME
4. PATH 상의 java
```

그래서 `JAVA_HOME`을 17로 맞춰놨는데 doctor는 21이라고 답하는 일이 생깁니다.
**doctor가 답한 쪽이 실제로 빌드에 쓰이는 자바입니다.**

**둘째, 프로젝트 안의 "17"은 JDK 버전이 아닙니다.**

`android/app/build.gradle.kts` 에 이런 줄이 있습니다:

```kotlin
sourceCompatibility = JavaVersion.VERSION_17
jvmTarget = ... JvmTarget.JVM_17
```

이건 **"만들어낼 결과물을 자바 17 형식으로 맞춰라"** 는 뜻이지
**"자바 17로 빌드를 돌려라"** 가 아닙니다. JDK 21로 돌려도 결과물은 17 형식으로 나옵니다.
이 17을 보고 JDK를 17로 내리는 게 아주 흔한 헛수고입니다.

### 범위 밖이면 이렇게 고정

```bash
# macOS
flutter config --jdk-dir="/Applications/Android Studio.app/Contents/jbr/Contents/Home"

# Windows
flutter config --jdk-dir="C:\Program Files\Android\Android Studio\jbr"
```

한 번 지정하면 계속 유지됩니다.

## 3. 서버 주소 설정 (.env)

서버 주소는 **사람마다, 그날그날 다릅니다.** 그래서 코드에 직접 적지 않고 `.env` 파일로 분리했습니다.

### 3-1. .env 만들기

```bash
cp .env.example .env          # Windows:  copy .env.example .env
```

`.env` 를 열어서 `SERVER_IP` 를 자기 상황에 맞게 고칩니다.

### 3-2. SERVER_IP 에 뭘 넣어야 하나

**이 표가 이 문서에서 제일 자주 보게 될 부분입니다.**

| 내 상황 | SERVER_IP 값 | 설명 |
|---|---|---|
| 에뮬레이터 + 서버가 **내 PC**에서 돎 | `10.0.2.2` | 에뮬레이터에서 `localhost`/`127.0.0.1` 은 **에뮬레이터 자기 자신**을 가리켜서 안 됩니다. `10.0.2.2` 가 "이 에뮬레이터를 돌리는 PC"라는 뜻의 특수 주소입니다 |
| 실제 폰 + 서버가 **내 PC**에서 돎 | 내 PC의 실제 IP | mac: `ipconfig getifaddr en0`<br>Windows: `ipconfig`<br>**폰과 PC가 같은 Wi-Fi여야 합니다** |
| 서버를 **팀원**이 돌림 | 그 팀원 PC의 IP | 공유기 재접속 시 바뀔 수 있으니 그때그때 확인 |

포트(`REST_PORT`, `MQTT_PORT`)는 서버 담당자가 바꾸지 않았다면 그대로 두면 됩니다.

### 3-3. 원리 (알아두면 좋음)

`.env` 값은 **빌드할 때 앱 안으로 구워집니다.** 앱이 실행 중에 `.env` 를 읽는 게 아닙니다.
그래서 **`.env` 를 고쳤으면 앱을 다시 실행해야** 반영됩니다. 핫 리로드로는 안 바뀝니다.

읽는 쪽 코드는 `lib/api_config.dart` 입니다:

```dart
static const String serverIp = String.fromEnvironment(
  'SERVER_IP',
  defaultValue: '192.168.0.6',   // .env 를 안 넘기면 이 값이 쓰임
);
```

별도 패키지 설치가 필요 없습니다. Flutter에 `.env` 를 읽는 기능이 내장돼 있습니다.

## 4. 실행

```bash
flutter clean          # 이전 빌드 찌꺼기 정리 (문제 생겼을 때만 해도 됨)
flutter pub get        # 라이브러리 내려받기
flutter devices        # 실행할 기기 목록 확인
flutter run --dart-define-from-file=.env
```

VS Code를 쓴다면 그냥 **F5** 를 누르면 됩니다. `.vscode/launch.json` 에 `.env` 를 읽도록 설정해 뒀습니다.

### ⚠️ 기기는 반드시 안드로이드 에뮬레이터나 실제 폰이어야 합니다

`flutter devices` 에 Chrome이나 macOS가 보여도 **고르면 안 됩니다.**

- **Chrome**: 빌드는 되지만 MQTT(실시간 센서값)가 브라우저에서 원천적으로 불가능하고, HTTP 요청도 CORS에 막힙니다
- **macOS**: 네트워크 권한이 없어서 통신이 전부 막힙니다

에뮬레이터가 목록에 없으면 Android Studio → Device Manager 에서 먼저 실행하세요.

## 5. .env 를 GitHub에 올리지 않는 법

### 왜 안 올리나

- `.env` 에는 **개인 PC의 IP** 가 들어갑니다. 사람마다 다르므로 공유하면 오히려 서로를 방해합니다
- 나중에 비밀번호·API 키가 들어가게 되면 **공개되면 안 되는 정보**가 됩니다
- 한 번 GitHub에 올라간 정보는 나중에 지워도 **커밋 기록에 영원히 남습니다**

### 어떻게 막나 — `.gitignore`

`.gitignore` 는 **"이 파일들은 git이 아예 못 본 척해라"** 라고 적어두는 파일입니다.
이 프로젝트의 `.gitignore` 맨 위에 이미 넣어놨습니다:

```gitignore
# 환경설정 (개인 IP/포트가 들어있으므로 절대 커밋하지 않는다)
# 공유가 필요하면 .env 가 아니라 .env.example 을 고쳐서 올릴 것
.env
.env.local
.env.*.local
!.env.example
```

마지막 줄의 `!` 는 **"이건 예외로 올려라"** 라는 뜻입니다.

### 두 파일의 역할 분담

| 파일 | git에 올라가나 | 용도 |
|---|---|---|
| `.env` | ❌ 안 올라감 | **내 개인 값.** 나만 씀 |
| `.env.example` | ✅ 올라감 | **템플릿.** 어떤 항목이 필요한지 팀에 알려주는 견본 |

**설정 항목이 새로 생기면 `.env.example` 에 추가해서 올리세요.** 그래야 다른 사람이 알 수 있습니다.

### 잘 되고 있는지 확인하는 법

```bash
git status
```

여기에 `.env` 가 **안 보이면 정상입니다.** 보이면 `.gitignore` 설정이 안 먹은 겁니다.

정확히 확인하려면:

```bash
git check-ignore -v .env
```

이렇게 나오면 제대로 무시되고 있는 것입니다:

```
.gitignore:3:.env	.env
 ↑ 어느 파일 몇 번째 줄의 규칙 때문에 무시되는지 알려줍니다
```

### 실수로 이미 올려버렸다면

`.gitignore` 는 **아직 git에 등록되지 않은 파일에만** 효과가 있습니다.
이미 커밋한 파일은 `.gitignore` 에 추가해도 계속 추적됩니다. 이때는 추적만 해제해야 합니다:

```bash
git rm --cached .env      # 파일은 그대로 두고 git 추적에서만 뺀다
git commit -m "chore: .env 를 git 추적에서 제외"
```

> ⚠️ 이건 **앞으로의 커밋에서만** 빠집니다. 과거 커밋 기록에는 그대로 남아 있습니다.
> IP 정도면 큰 문제가 아니지만, **비밀번호나 API 키를 올렸다면 그 값 자체를 반드시 새로 발급받으세요.**
> 기록에서 지우는 것보다 값을 무효화하는 게 확실합니다.

## 6. 에러 읽는 법

### 규칙 하나만 기억하세요

빌드 에러는 수백 줄이 쏟아지지만, **진짜 원인은 `* What went wrong:` 바로 아래 한 블록**에 있습니다.
나머지는 대부분 "옵션을 붙여서 다시 돌려봐라" 같은 안내문입니다.

```bash
flutter build apk --debug 2>&1 | tail -40
```

마지막 40줄만 보면 충분합니다.

### 어느 쪽 문제인지 1초 만에 구분하기

| 에러에 이런 단어가 보이면 | 어느 문제인가 |
|---|---|
| `Gradle`, `Task :app:`, `jlink`, `Kotlin` | **빌드 문제** — 내 PC 환경 |
| `Socket`, `Connection`, `HTTP`, `서버 연결 실패` | **서버 문제** — 내 잘못 아님 |

### 자주 만나는 에러 대응표

아래는 전부 실제로 재현해서 확인한 것들입니다.

| 에러 메시지에 이 문구가 있으면 | 원인 | 해결 |
|---|---|---|
| `Gradle requires JVM 17 or later to run.`<br>`configured to use JVM 11` | JDK가 **너무 낮음** | JDK 17~21로 교체 (2장) |
| `JdkImageTransform`<br>`jlink`<br>`core-for-system-modules.jar` | JDK가 **너무 높음 (26+)** | JDK 21로 교체 (2장)<br>메시지가 원인을 전혀 안 알려주는 악질입니다 |
| `Some Android licenses not accepted` | SDK 라이선스 미동의 | `flutter doctor --android-licenses` |
| `No devices found` | 에뮬레이터를 안 켬 | Android Studio → Device Manager |
| `Connection refused`<br>`SocketException`<br>`❌ 서버 연결 실패` | **서버가 꺼져 있음** | 서버 담당자에게 연락.<br>**앱 문제가 아니므로 코드를 고치지 마세요** |
| `Unsupported Kotlin plugin version` | 단순 경고 | **무시해도 됩니다.** 빌드는 정상입니다 |

### 문제가 생겼을 때 순서

```
1단계  flutter clean && flutter pub get        ← 대부분 여기서 해결
2단계  flutter doctor -v  로 JDK 확인
3단계  cd android && ./gradlew clean
4단계  rm -rf ~/.gradle/caches                 ← 최후의 수단, 재다운로드에 오래 걸림
```

> **JDK가 잘못된 상태에서 캐시만 지우는 것은 아무 의미가 없습니다.**
> 지우고 다시 받고를 반복하면서 몇 시간을 태우는 가장 흔한 패턴입니다.
> 캐시를 지우기 전에 **반드시 2단계를 먼저** 하세요.

## 7. 하지 말아야 할 것

| 하지 말 것 | 왜 |
|---|---|
| `flutter upgrade` / `flutter downgrade` | 프로젝트가 만들어진 Flutter 버전이 정해져 있습니다. 옮기면 없던 문제가 생깁니다 |

| `android/` 폴더 삭제 후 재생성 | 앱에 추가해둔 **인터넷 권한이 날아가서** 통신이 안 됩니다 |
| `.env` 를 git에 커밋 | 5장 참고 |
| 서버 에러가 났을 때 앱 코드 수정 | 원인이 앱에 없습니다. 고칠수록 망가집니다 |

## 8. 자주 묻는 것

**Q. 앱은 뜨는데 로그인하면 `서버 연결 실패` 가 나요**
서버가 꺼져 있거나 주소가 틀렸습니다. 순서대로 확인하세요.
1. 서버 담당자가 지금 서버를 켜뒀는가
2. `.env` 의 `SERVER_IP` 가 그 사람 PC의 **현재** IP가 맞는가 (공유기 재접속 시 바뀝니다)
3. 나와 그 PC가 **같은 Wi-Fi** 인가

**Q. `.env` 를 고쳤는데 안 바뀌어요**
`.env` 값은 빌드할 때 앱에 구워집니다. **앱을 완전히 껐다 다시 실행**하세요. 핫 리로드로는 안 바뀝니다.

**Q. 어제는 됐는데 오늘 안 돼요**
십중팔구 서버 담당자 PC의 IP가 바뀐 것입니다. `.env` 의 `SERVER_IP` 를 다시 확인하세요.

**Q. 팀원은 되는데 저만 안 돼요**
`flutter doctor -v` 결과를 서로 비교하세요. 특히 **Java version** 줄입니다.

**Q. 빌드가 너무 오래 걸려요**
